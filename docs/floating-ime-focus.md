# 浮动 TV 键盘与账号焦点

用户在 Android 6 实测确认：手机号输入框能取得焦点，系统键盘能弹出，但方向键无法操作键盘；“检查更新”没有明显的焦点高亮。

旧原生处理只通过可见窗口高度判断键盘。浮动 TV 键盘不一定缩小窗口，因而 KEYCODE_DPAD_UP/DOWN 被原生转给网页导航。网页在编辑输入框时也会处理上下键，使焦点离开输入框、停止编辑。

现在原生 InputKeyPolicy 优先考虑已开始的账号输入会话，编辑时不截取上下键。网页也保留编辑中的四个方向键，不调用页面焦点路由。WebView 的 onKeyPreIme 在编辑时处理完整的 Back 按键对，不依赖浮动键盘的窗口高度变化来完成输入。停止编辑后恢复只读导航；原生键盘关闭后恢复全屏，不发送短信或登录。重复点击正在编辑的输入框不重启输入连接。后台仍结束编辑。

手机号、验证码设置明确 tabindex=0。账号输入和账号按钮同时支持 :focus 与 .is-focused，并使用白色圆角边框与亮背景。“下载设置”入口及其页面引用已移除，原生更新的代理与直连容错保留。

播放器 SVG 使用原有 sprite 与 xlink:href。动态集数、季数、倍速、清晰度和音量均只更新 .control-label，避免整颗按钮的 textContent 清除图标。Android 音量按钮保持隐藏。

本机浏览器只验收网页路由、样式和模拟桥；InputKeyPolicy 的浮动键盘回归由 GitHub 原生 JVM 测试验证。实体 Android 6 的输入法仍需覆盖安装后复测。
