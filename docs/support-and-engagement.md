# 打赏页面与播放计数

打赏入口沿用左侧导航。两张本机 PNG 只使用用户确认并清除姓名的版本，随 Go 核心嵌入 APK；没有原图姓名、作者或联系方式。二维码本身逐像素保留。两张卡片左右切换，确认放大、关闭/返回恢复入口。旧 WebView 使用 flex 和 margin，图片以原比例展示。

文案：
> 喜欢这里？请我喝杯咖啡
>
> 如果这里让你少花一点找剧的时间，多一点追剧的快乐，欢迎请我喝杯咖啡。你的支持，会成为继续打磨体验、保持更新的一份动力。
>
> 一杯咖啡，一份鼓励。谢谢你，让这里变得更好。

统计使用官方 `/novel/player/multi_video_detail/preload/v1` 的 `video_data.followed_cnt`（整部剧收藏）及 `video_list` 中精确 VID 的 `digged_count`、`comment_count`（当前集）。缺失评论计数时沿用已确认的当前 VID 评论接口读取 total。不会拿整部剧 digg_cnt 冒充当前集点赞，也不会用第一集的评论数替代后续集。

本机 `/api/v1/player/stats` 仅允许同源访问，与其他播放器接口一致；统计读取不解析媒体、不阻塞播放，不写账号云端。UI 最多缓存48个剧/集组合45秒，切集取消旧请求并核对完整字符串 ID；换账号清缓存。缺失或读取失败显示“—”，真实0显示“0”。本机确认点赞/收藏后调整当前展示，重新读取以上游为准；收藏云同步仍按原有队列执行。

自动更新功能沿用0.2.8，可用于本轮0.2.9覆盖升级。浏览器旧API模拟、接口/ID隔离测试、APK/证书/嵌入图片校验与Android6真机安装/扫码验收分别记录。

## Android 登录输入与方向键

账号输入框保持自然可编辑，使用 WebView 原有数字键盘连接；原生桥只登记输入状态，不重建输入连接或强制唤起输入法。编辑时方向键和确认键交给系统键盘，返回键、完成键或输入法关闭后保留输入内容，焦点转到获取验证码或登录按钮。输入结束不会自动发短信或登录。已发验证码的手机号仍锁定，换号沿用独立按钮。

原生桥只在本机页面就绪且前台时登记编辑；切换页面或退后台会结束编辑。手机号和验证码的真实 Android 输入法行为需通过 APK 在 Android 6 设备复测，浏览器只验证焦点路由和桥调用。0.2.11 键盘操作已获用户实机确认，0.2.12 输入完成后的焦点修复仍待实机复测。

“我的 / 登录”删除下载代理的技术说明行，入口改名“下载设置”。更新器原有下载容错继续生效。

## 扫码辅助上行短信

遇到红果返回的上行短信验证时，由服务端提供的号码与内容在本机生成 `SMSTO:号码:内容` PNG 二维码。码中不包含登录手机号、验证码、账号凭证或外部链接。二维码使用公开 Go 编码库，没有外部生成服务；只在内存中的本次 MFA 会话保留。手机扫码工具可能打开短信编辑，也可能显示可复制文本，因此仍保留号码与内容，发送始终由用户确认。确认键可放大，返回恢复二维码卡片，向下到“我已发送”。

三个阶段分别计时：验证码登录的本机10分钟期限从获取验证码时算起；新的上行短信挑战收到后，单独开始10分钟本机等待期限，前面的输入耗时不计入这次等待。红果可能提前拒绝，这些本机期限不是红果官方保证的 TTL。界面明确展示本机剩余时间。扫码、打开大图、读取状态和再次查询均不续期。到期会中止正在查询的请求、清除会话与二维码、回到获取新验证码。服务端明确返回“验证已过期”等结果时，也清除已失效挑战并保留上游错误代码，区别于本机等待结束。

90秒仅是用户点“我已发送”后的一轮结果等待。轮询每3秒一次，到90秒取消未完成请求并恢复“再次查询”；未过期的会话仍保留，用户无需重复发送短信。未点击前不轮询；关闭页面、退后台或取消验证会停止本轮。错误和迟到响应不会重启轮询，也不会跨到新会话。独立假时钟测试验证实际计时与取消，而不是只核对文案。
