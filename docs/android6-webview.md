# Android 6 界面启动与播放显示修复

## 原因和修复

Android 系统版本不代表 WebView 已更新。Android 6 原始 Chromium 44 不支持 `NodeList.forEach`、`URLSearchParams`、`AbortController`、`Element.closest` 等接口，且 `HTMLMediaElement.play()` 返回 `undefined`。旧脚本在事件注册阶段直接中断，状态栏因此停留在“连接核心服务…”，尚未请求核心状态。

`compat.js` 先于主脚本加载，补齐使用到的 ES5/DOM 接口，并通过 XHR 提供 JSON 请求和取消能力。`playMedia` 兼容 `play()` 的旧返回值。触摸事件使用布尔参数，避免旧浏览器把事件选项对象当成捕获模式。旧版滚动实现只滚动溢出的父容器，保持遥控器焦点可见。

CSS 改用明确的颜色和定位属性，焦点样式不再与不支持的 `:focus-visible` 共用选择器。Grid、Flex gap、海报比例根据实际能力降级为 Flex、margin 和固定比例容器。宽高和字号函数保留可用的普通声明。所有布局兼容分支仅影响缺少对应能力的浏览器。

Android 壳最多等待 30 秒取得自己启动的 Go 子进程地址，并核对实例标识和精确构建版本后才加载页面；失败提供“重试”。不再接受固定端口上任意服务的健康响应。页面状态请求最多等待 8 秒，静态资源禁止缓存。播放设置在 APK 中保存到 SharedPreferences，避免端口变化后丢失；账号、记录和媒体缓存仍位于各自的应用私有目录。详见 [正式构建与核心身份](release-runtime.md)。

## 选集和背景

网页 `locked` 标记仍可存在于详情数据，但不再改变按钮亮度或可点击状态。所有集数样式相同，当前集粉色，焦点白框；当前集获得焦点时仍保持粉色。

准备新推荐、新集或重试时增加 `is-preparing-video`，显示海报并暂时隐藏视频。收到当前视频 `playing` 后移除；已解码但暂停的 `canplay` 也切换到视频画面。播放、暂停、普通缓冲和拖动不重新显示海报。视频容器及两侧为黑色。换清晰度不重新展示海报。

## 验证

- 修复前在缺少 `NodeList.forEach` 的浏览器环境复现状态一直停在“连接核心服务…”。
- 修复后移除旧版缺失 API、模拟 `play()` 返回 undefined、禁用不支持的 CSS 声明，1280×720 和 1920×1080 下能初始化和播放。
- 测试详情标记第 4 集起 locked，确认 80 集亮度一致，第 8 集实际进入测试播放；当前集粉色和白框同时存在。
- 验证准备 → 播放 → 暂停 → 缓冲 → 换集的背景状态，列表、海报、排行榜尺寸和遥控器焦点。
- `tests/compat.test.cjs` 覆盖缺失 API、Unicode、查询编码、XHR 状态、错误、超时、取消、重复初始化和焦点滚动；已有分页测试继续通过。
- Go 静态资源测试确认六个界面文件嵌入并禁止缓存。

浏览器模拟验证不能代替真实 Android 6 WebView 和设备的视频解码、长时间播放验收。Android 壳的编译和 lint 在 GitHub Actions 完成。
