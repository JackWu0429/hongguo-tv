# 切剧加载显示

0.2.14 修复两处显示问题：旧 Android WebView 在重置视频源时可能闪出灰色视频矩形；全屏/控件隐藏时，下一部剧的 loading 有海报但没有剧名。

开始切剧时保留原来的全屏和控件状态，清除旧控件隐藏计时器，先进入准备状态、更新新剧名/集数与 loading，再暂停并重置旧视频源。视频层不仅 opacity=0，还使用 visibility:hidden；无 source 时也保持隐藏。推荐容器和媒体底色均为黑色，海报解码后按原比例 cover 显示，视频首帧可用后隐藏海报并恢复视频层。

控件隐藏时只覆盖准备状态的 hero-top-copy 可见性，不重新打开按钮、进度条、侧栏或整组控件。准备结束后名称恢复原来的隐藏状态；暂停和播放中缓冲仍保留视频画面，不重新进入海报准备状态。

2026-10-08 的隔离 fixture 使用本机生成的 MP4、不同的海报和延迟播放信息接口，强制 Chromium 44 缺失 API 与旧布局。验证重置 load() 时 video 的计算可见性为 hidden，新剧名先显示；播放后视频可见、海报隐藏，原控件隐藏状态保留。覆盖普通/全屏、正常播放、暂停、中途缓冲和快速上下切换，没有真实媒体解析或云端写入。

浏览器可以验证 DOM 状态和加载顺序，不能证明 Android 6 硬件视频层完全没有灰块。最终视觉需用正式 APK 复测。

## 0.2.15 加载提示与目标集号

解析、下载、绑定视频源及首次 waiting 共用“正在加载第 N 集…”和同一 spinner 元素，不人为增加延迟。首次进度还未读取时仅显示加载提示和剧名，确认目标集数后再显示集号；手动选集、同季自然续播与历史续播在读取详情前就使用目标集数，避免推荐卡片缺少 start_episode 时误显示第1集。播放中 waiting 仍显示“正在缓冲…”，保留视频画面。playing 或可显示的就绪帧结束加载。

浏览器记录第2集手动选择和第3集自动续播全过程，解析和首帧阶段动画未重建或中断，顶部集号正确。原有同季下一集提前准备、下载和缓存阈值保持不变。

## 0.2.18 同剧切集与纯黑过渡

用户实机确认 0.2.17 换集速度已改善，但短暂出现的海报造成闪烁；此前视频源重置前的灰块仍存在。因此 0.2.14 的 visibility 隐藏不能视为 Android 6 实机已修复。

同一部剧已经播放后，自动下一集和手动选集不显示加载海报，保留同一个 loading 和准确的目标集号。首次打开及切换其他剧（包括下一季的不同 series_id）继续显示海报。切换前根据原播放对象判断，避免 feedItems 已被替换后误判；快速切换到另一部剧会清除旧的同剧状态。

视频容器底色统一为纯黑。独立的不透明过渡背景位于视频层上方、标题和原加载提示下方；海报放在这层内，同剧切集时隐藏。开始切换后先隐藏旧视频并等待一次实际绘制边界，再暂停、清空并 load 视频源。实现使用两次 requestAnimationFrame，让两次回调之间发生一次绘制，不设置固定的 loading 最短时间。取消请求、代次失效、离开前台都会阻止迟到回调重置或绑定旧视频；历史等待同时进行，保留自动下一集不等待完成记录写盘的路径。

canplay 不再结束准备状态。playing 到来后先让新视频在不透明过渡层下恢复可见，经过绘制边界后才撤掉过渡层和原 loading；若期间暂停、缓冲或发生新切换，旧回调保留当前过渡。播放中的普通缓冲仍保留视频画面，不重新显示海报。playing 与绘制边界只能验证浏览器时序，不能等同于 Android 硬件屏幕首帧的精确确认。

回归包含真实本机合成 MP4、旧 API/布局模拟、同剧自动与手动选集、canplay 提前触发、暂停/缓冲/失效回调、不同推荐与全屏。77 项 Node 测试、12 项 Python 测试及 Go race/vet 通过；Android 6 硬件灰块与最终视觉仍需正式包实机复测。
