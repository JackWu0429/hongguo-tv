# Linux 播放可行性验证

2026-10-19，在 GitHub Actions Ubuntu 24.04 x86_64 上通过真实播放验证。
[通过的运行记录](https://github.com/aston314/hongguo-tv/actions/runs/39274660986)，验证代码为 `f49e083`，应用代码基于 `be3fa3a`。

## 环境与实际路径

- Wails 2.11.0、GTK 3.24.41、WebKitGTK 2.52.6、GStreamer 1.24.2。
- Xvfb / 软件图形；安装 `gstreamer1.0-libav`，将 `avdec_h265` 的优先级设为 300。
- 使用现有 `coreHost` 启动新建访客目录中的真实 Go 服务，经过正常的就绪标识和版本一致性检查。
- 通过共享页面现有的 `openHomeProgram` 进入单剧播放，使用原来的 `#hero-video` 和现有方向键切集逻辑。
- 实时请求红果详情和播放地址，经过现有签名、解密、Range 代理；没有把播放器替换为 MPV、Chromium 或本地样片。
- 剧集《神豪外挂第一季》，ID `7696023326375808024`；第 1、2 集均由 `ffprobe` 确认为 **HEVC 1282×720 + AAC 44.1 kHz 双声道**。
- 两集播放准备均返回 HTTP 200、`mode=range`。第 3 集的预取请求也成功，但未将预取成功算作播放通过。

## 保存的证据

| 检查 | 实测结果 |
| --- | --- |
| 第 1 集持续播放 | 2.084 → 9.146 秒，解码帧 61 → 273，约 30 FPS，报告掉帧为 0 |
| 拖动进度 | 约 9 秒跳到约 21 秒，收到 `seeked`，继续播放到 22.288 秒并截到新画面 |
| 切到第 2 集 | 使用现有 ArrowDown 处理路径；新源自行开始播放，无需再次按播放键 |
| 第 2 集持续播放 | 2.015 → 8.813 秒，解码帧 61 → 265，约 30 FPS，报告掉帧为 0 |
| 真实画面 | 从 X11 合成器截图，检查非黑像素和画面变化，并人工查看两集截图 |
| 音频解码 | PulseAudio null sink 的监视输出中，两集均有约 2 秒非零 PCM，RMS 分别约 5380、5429 |

未假设 WebKit 支持 `requestVideoFrameCallback`：本次该计数为 0，使用浏览器报告的解码帧数、推进的播放时间及真实合成器画面交叉验证。

## 自动播放与验证范围

首次进入采用程序调用，尚无真实用户输入。视频已解出画面但暂停在 0 秒；通过 XTEST 模拟一次真实 Space 键，走应用原有播放处理后正常播放。之后切到第 2 集不需要第二次播放操作。

这证明当前 HTML5 路径可以在上述 Linux 环境播放真实 HEVC 视频；首次自动播放的用户手势要求仍须在 Linux 产品适配时处理。没有验证用户真实点击卡片的完整手势链，也没有验证看完本集后自动连播。

本次没有验证实体显卡、实体扬声器、其他发行版、低性能机器、1080p、安装包或长期稳定性。约 30 FPS 的结果仅对应本次 720p 片段，不能推广为所有 Linux 设备的性能保证。

探针未运行桌面自动更新任务。现有正式打包、平台识别和更新清单仍只覆盖 macOS / Windows；制作 Linux 安装包时必须单独接入，不能直接沿用当前打包脚本的 Windows 分支。
