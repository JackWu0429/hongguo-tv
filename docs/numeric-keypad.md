# 账号数字键盘

0.2.13 将手机号和验证码字段改成按钮，确认后打开应用自己的数字键盘。这两个字段没有可编辑 input，不调用系统 IME 编辑桥；搜索、评论等文字输入保持原有方式。

键盘布局为三列四行：1–9，最后一行是“删除 / 0 / 完成”。首次打开焦点在 1。方向键按行列移动，边界停留，不环绕到侧栏或页面其它按钮。支持实体数字键、删除键和确认键；确认键长按不会重复触发完成。Tab 留在键盘内，意外的外部 focus 会回到当前键。焦点用实际白色圆角边框绘制。布局使用 flex、百分比减固定边距和 margin，不依赖 grid 或 flex gap。

手机号最多 11 位，完成时检查号码格式；验证码为 4–8 位字符串，保留前导零。每次输入同步到原字段，返回键保留部分输入，下一次打开继续修改。完成后手机号转到获取验证码，验证码转到登录；已发码但补输入手机号时转到验证码字段。完成操作本身不发网络请求。

切页、后台或账号阶段变化时关闭失效键盘，不保留隐藏按键焦点。更新提示在键盘打开期间禁止弹出。旧原生 IME 完成回调不参与数字键盘状态，避免迟到回调关闭新键盘。原生桥仍保留供兼容，其它文字输入未改。

验证包含独立状态测试、旧 DOM keyCode 路由及浏览器实际 DOM 操作。2026-10-08 隔离 fixture 强制移除 Chromium 44 缺少的 API、强制旧 CSS 路径，28 项焦点/交互检查通过；账号阶段变化会关闭键盘并恢复可见焦点。960×540、1280×720、1920×1080 均保持三列四行，无横向溢出，焦点为 9px 圆角白边。账号测试没有触发系统输入桥，没有真实发送短信或修改云端数据。

2026-10-08 用户已在设备上验证 0.2.13 数字键盘功能正常。本轮播放显示修改不改数字键盘。后续输入方式扩展仍需独立验证，不能据现有键盘验收直接判断扫码回填或其它系统输入方式。
