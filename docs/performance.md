# 性能说明

数字来自海信 VIDAA（Android 9，32 位用户空间，MTK9632，`MemTotal` 约 1.25GB）上 `HGSWITCH` 日志。机型是 Vidda 55V1F-R。下面只写测到的结果。

## 播放器只留一个

这台电视的 HEVC 硬解是 `OMX.MS.HEVC.Decoder`。页面里的 HTML 视频会报 `playing`，解码器接着报 `NoSupport`，画面出不来。旧路径再空等 1 秒，才冷启动 Media3。

1.0.0 在有 Media3 桥接时从第一帧就留在桥接上，不再把地址交给 HTML 视频，也不再为这一下等 1 秒。没有加第二个 ExoPlayer。

测到的变化：自动下一集从「固定再等 1000 毫秒」变成预取命中后直接进 Media3。第一次打开一部剧仍然要等播放信息，这一段从大约 0.5 秒到十几秒都出现过。

## 下一集提前准备

当前集开始播放后就准备下一集的同一段 Range 地址。不把整集下完，也不把锁定集改成完整可播。

预取没命中时，自动换集要现取地址。日志里有一次第 5 集到第 6 集用了 7200 毫秒。预取命中后，同一次播放里测到：

| 切换 | 按键到出画 | 说明 |
| --- | --- | --- |
| 第 43 集手动打开 | 4185 毫秒 | 第一次，还没预取 |
| 第 43 集到第 44 集 | 412 毫秒 | `prepared=1`，出画 386 毫秒 |
| 第 80 集接到第 81 集 | 297 毫秒 | 还剩 416 毫秒时提前接上，出画多 99 毫秒 |

海信这颗解码器在 `STATE_ENDED` 之后不再画出下一集。所以下一集已经排上、当前还在播、离结束不超过 700 毫秒时，用同一次 `seekTo` 接过去。最后大约 0.4 到 0.7 秒不会再画出来。2.5 秒内如果没有新画面，再重开这一集。

这不是无缝到听不出切换，也没有测到 200 毫秒以内。出画这一步单独就可以超过 200 毫秒。

## 内存

整机大约 1.25GB，内核占去约 513MB。没有卸载当贝桌面，没有清系统缓存来换播放速度，也没有再开一个解码器。

## 安装包

32 位包只带 `armeabi-v7a`，给这台 VIDAA。64 位包只带 `arm64-v8a`。两个包都是标准版 Media3，不是 MPV 版。
