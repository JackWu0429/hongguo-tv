# 观看历史筛选

历史页提供「全部」「未看完」「已看完」。选中态与遥控器焦点分开，进入历史时默认「全部」，离开页面或播放返回时保留本次会话的选择。账号身份变化后恢复「全部」。

## 判断规则

与 Mac v1.1.6 保持一致：已有观看记录、已知总集数、最近观看集数达到总集数，就归入「已看完」。这里表示已看到最后一集，不要求最后一集自然播放结束。多季短剧按其独立 `series_id` 判断，不表示整个系列看完。

仍在中间集、总集数未知，归入「未看完」。云端旧记录无需包含 `completed`。重新播放最后一集仍归入「已看完」；重新从第一集观看或总集数增加后尚未到新末集，归入「未看完」。

`completed` 继续仅作为单集结束与断点续播依据：末集没播完时仍从该集的保存时间续播，不因为历史显示「已看完」而跳回第一集。云端 `duration` 可能是整部剧总时长，不用于筛选。

## Mac 版证据（2026-10-08）

发布版嵌入前端的 `History` 组件直接使用以下判断，同一个方法同时控制筛选与「已看完」标签：

```javascript
function p(I) {
  const B = I.series ? I.series.episodeCount : 0;
  return B > 0 && I.episodeIndex + 1 >= B;
}
```

Mac 的 `episodeIndex` 从 0 起算；TV 的 `episode` 从 1 起算，所以 TV 对应为 `episode >= episode_count`。Mac 的 `HistoryItem` 只包含 `series / episodeIndex / videoId / positionSec / updatedAt`，没有 `completed`。0.2.24 额外要求单集结束，导致云端末集记录被排除；0.2.25 修正此差异。

静态证据来自 v1.1.6 x86_64 安装包，二进制 SHA256 `4dc6d24ad9ce5f4d09a0fa0d94c6cc1e8a253cf755c2c6f8de214a3c100b0dbc`，`History` 组件偏移 `0x9a81d5`。本机提取和只读真实历史对照位于工作区 `tmp/hongguo-history-mac-alignment-20261008/`，不执行原应用。

## 展示与操作

先筛选完整本机/同步记录，再按观看时间排序及每批 20 部滚动加载，不设记录总数上限。切换筛选重置当前批次和滚动位置；播放返回保留筛选、已显示数量及仍存在的卡片焦点。若卡片因观看状态改变退出当前筛选，焦点回到列表中的可用卡片或当前筛选按钮。

方向键在筛选行左右移动，左边界进入侧边栏；向下进入卡片，卡片首行向上返回当前筛选。空列表向下可进入「去找剧」，向上返回筛选。筛选不写入存储、不调用云端修改接口，也不影响收藏/点赞。

「管理」移除当前选定的历史记录；「清空」仍为清空全部历史，保留原来的确认弹窗和明确的范围说明。

## 验证

`tests/history-filters.test.cjs` 覆盖末集进入但未结束、旧云端记录无结束标记、中间集结束、排序和数据不变、收藏/点赞隔离、筛选前分页、重看及总集数增加、断点续播保持。0.2.24 的隔离浏览器已检查 960×540、1280×720、1920×1080 布局及遥控器导航、分页到底、空结果和播放返回，禁用新 WebView API 和 Flex gap；0.2.25 再核对修正规则与播放返回。未替代 Android 6 实机验收。
