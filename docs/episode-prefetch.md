# 同季下一集后台准备

独立 TV APK 在当前集连续稳定播放 5 秒后，检查详情中后续最多 4 个未锁定 VID，并只为紧邻的下一集做一次播放准备；不同时下载多集，不挂载第二个视频元素。WebView 自动按需读取时，准备只解析签名地址并建立 Range 索引，不下载整集；MPV 保持现有标准准备路径。

## 触发与范围

- 当前集已连续稳定播放 5 秒，按真实经过时间判断，不按播放位置判断。历史续播、倍速、拖动到后段不会立即触发；暂停、缓冲、跳转后重新计算稳定时间。已经启动的同上下文任务继续复用。
- 页面可见、应用在前台且视频正在播放，清晰度切换期间不触发。
- 每次播放上下文只尝试一次。VID 候选最多向后检查 4 集，过滤 locked/不可访问集；只有紧邻下一集可播放时才准备它，不跨过锁定集自动跳集。
- 当前季最后一集不预备其他季，也不下载下一条推荐。
- 下一季确认、未上线预约和自然续播规则保持现有行为。

## 复用与取消

`ui/episode-prefetch.js` 保存单个可取消任务，按剧、当前 VID、集数、清晰度、播放代次和账号代次隔离。后台调用现有 `/api/v1/play/info`，带 `prefetch=1`。Range 预取失败只静默放弃，不会回退成整集下载；前台真正切集时重新请求，仍可自动切标准播放。不改变当前视频地址、焦点、加载反馈或观看记录。

自然换集可以接管仍在等待详情或下载的任务。取得结果后，前台再次调用正常播放接口确认准备结果仍有效；整集模式直接复用已准备文件，Range 模式复用内存中的初始化索引。预备失败仅结束后台任务，实际换集仍正常重试，前台 Range 准备失败时允许回退标准整集播放。

0.2.17 为同季自然下一集增加历史保存并行路径：ended 先提交本集完成记录，下一集的明确集号和起始位置不依赖这次写盘结果，因此不重复提交完成记录、不等待保存队列才解析或打开文件。写入继续按原队列顺序完成，下一集的播放记录排在本集之后，失败仍显示保存提示。只在原播放代次、账号代次、同剧相邻集、完成状态和已经读取历史均匹配时使用；首次播放、历史续播、手动选集及账号切换继续走原历史读取/等待路径。

切剧、选择不相邻的集、清晰度改变、切换账号、离开播放页面或进入后台时取消失效任务。前台接管后的任务仍由前台管理取消。准备被后台或账号切换中断时，保留可达的“重试播放”按钮，不自动抢占播放。

Go 按原有剧/VID/清晰度/回退策略缓存键共用准备任务。每个等待请求独立退出；最后一个等待者退出才取消下载。相同键的取消任务清理完成后才允许新任务写入，避免旧任务删除新文件。下载错误删除半成品；缓存失败和缺失文件均允许重试。

## 缓存及效果边界

保留现有 512 MiB 完成文件缓存清理阈值、2 小时 TTL 和 512 MiB 单集下载上限。一次最多新增一个后台准备任务；下载中的文件和暂时被请求使用的文件可能让瞬时占用超过清理阈值。缓存清理继续按最近使用时间执行，不保存整季。

0.2.6 补齐重启后旧进程目录的回收，详见 [名称、导航与媒体缓存](navigation-and-cache.md)。旧版只有当前进程目录参与清理，不能据此保证跨重启总量不会累积。

解析和 Range 索引可提前完成，但媒体字节仍由当前播放器按需读取，视频解码和起播仍需要时间。网络慢、提前准备失败或刚开始播放便手动换集时，依然可能出现正常的播放 loading。最多 4 集是 VID 候选窗口，不是 4 集媒体预下载，也不扩大现有缓存占用。

## 验证

- Node 测试覆盖稳定时间、一次触发、同季边界、迟到详情、账号/清晰度隔离、任务接管、静默失败和旧 WebView 兼容；新增播放流程测试让完成记录写盘保持未返回，验证下一集先起播、记录有序保存、不重复写完成状态、失败后仍能继续保存，以及退出后的迟到回复不绑定旧视频。
- Go race/vet 和全量测试覆盖准备任务共享、单消费者退出、最后消费者取消真实 HTTP 数据流、半成品删除、失败重试、缓存文件丢失及同键清理顺序。
- 隔离浏览器以模拟媒体时钟，在 1280×720、1920×1080 和缺失 fetch/AbortController/URLSearchParams 等旧环境验证换集、焦点、历史、切剧、清晰度、跳集、后台、账号变更和重试。没有请求真实账号写接口。
- APK 由 GitHub Actions 签名构建；实体 Android 6 换集延迟与长时间播放仍需设备复测。

## 0.2.17 隔离对比与计时

90 秒本机合成 MP4、相同的 2 秒完成记录写盘延迟、旧 API 与旧布局模拟条件下，0.2.16 自动换集出现两次完成写入，约 4029ms 后下一集 playing；0.2.17 只提交一次完成写入，约 14ms 后下一集 playing，完成记录当时仍在等待，随后本机历史正常更新为第2集。新预下载在播放约 5.5 秒时已开始。该对比证明写盘等待移出起播路径，不代表 Android TV 设备或真实网络会达到同样毫秒数。

预下载与完成写入同时失败的 fixture 中，正常播放接口仍解析并起播第2集，历史保存错误有提示，后续第2集记录保存成功。暂停 5 秒、恢复 3 秒以及缓冲后 3 秒均未启动新任务，恢复连续稳定 5 秒后只启动一次。

`window.HongguoTVPlaybackTiming.snapshot()` 提供最近最多 20 次成功起播的内存计时：集数、自动下一集标志、预下载耗时、是否在切换前准备完成、文件就绪耗时、文件就绪到 playing 的耗时及总耗时。未包含剧名、ID 或账号信息，不落盘、不上传。playing 是浏览器播放事件，不能等同于硬件屏幕首帧精确呈现。加载提示持续到原播放就绪事件，不使用人为延迟。
