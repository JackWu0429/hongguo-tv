# 同季下一集后台准备

独立 TV APK 在当前集接近结束时，使用内置 Go 解析、下载和 CENC 解密下一集，减少换集时的准备等待。使用现有播放器，不挂载第二个视频元素。

## 触发与范围

- 当前集已开始播放至少 5 秒，播放进度达到 62%，或剩余时间不超过 45 秒。
- 页面可见、应用在前台且视频正在播放，清晰度切换期间不触发。
- 每次播放上下文只尝试一次，只准备详情 `vid_list` 中的下一集。
- 当前季最后一集不预备其他季，也不下载下一条推荐。
- 下一季确认、未上线预约和自然续播规则保持现有行为。

## 复用与取消

`ui/episode-prefetch.js` 保存单个可取消任务，按剧、当前 VID、集数、清晰度、播放代次和账号代次隔离。后台调用现有 `/api/v1/play/info`，不改变当前视频地址、焦点、加载反馈或观看记录。

自然换集可以接管仍在等待详情或下载的任务。取得结果后，前台再次调用正常播放接口确认缓存文件仍存在；Go 直接返回已准备文件，不重新下载。预备失败仅结束后台任务，实际换集仍正常重试。

切剧、选择不相邻的集、清晰度改变、切换账号、离开播放页面或进入后台时取消失效任务。前台接管后的任务仍由前台管理取消。准备被后台或账号切换中断时，保留可达的“重试播放”按钮，不自动抢占播放。

Go 按原有剧/VID/清晰度/回退策略缓存键共用准备任务。每个等待请求独立退出；最后一个等待者退出才取消下载。相同键的取消任务清理完成后才允许新任务写入，避免旧任务删除新文件。下载错误删除半成品；缓存失败和缺失文件均允许重试。

## 缓存及效果边界

保留现有 512 MiB 完成文件缓存清理阈值、2 小时 TTL 和 512 MiB 单集下载上限。一次最多新增一个后台准备任务；下载中的文件和暂时被请求使用的文件可能让瞬时占用超过清理阈值。缓存清理继续按最近使用时间执行，不保存整季。

下载和解析可提前完成，但视频解码和起播仍需要时间。网络慢、提前准备失败或刚开始播放便手动换集时，依然可能出现正常的播放 loading。

## 验证

- 32 项 Node 测试覆盖阈值、一次触发、同季边界、迟到详情、账号/清晰度隔离、任务接管、静默失败和旧 WebView 兼容。
- Go race/vet 和全量测试覆盖准备任务共享、单消费者退出、最后消费者取消真实 HTTP 数据流、半成品删除、失败重试、缓存文件丢失及同键清理顺序。
- 隔离浏览器以模拟媒体时钟，在 1280×720、1920×1080 和缺失 fetch/AbortController/URLSearchParams 等旧环境验证换集、焦点、历史、切剧、清晰度、跳集、后台、账号变更和重试。没有请求真实账号写接口。
- APK 由 GitHub Actions 签名构建；实体 Android 6 换集延迟与长时间播放仍需设备复测。
