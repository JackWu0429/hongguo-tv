# 2026-10-23 换集预取、遥控器焦点、直连 Media3

## 背景

海信 VIDAA（Android 9，32 位用户空间，MTK9632，约 1.3GB 内存）上，克隆包 `rocks.aston.hongguotv.debug` 换集要等几秒。电视日志把原因分成两段。

第一段在地址拿到之后，每一集都先走页面里的 HTML 视频。这台电视的 HEVC（`hvc1.1.6.L186`）在 WebView 里会发出 `playing`，但 `OMX.MS.HEVC.Decoder` 报 `NoSupport`，画面出不来。代码再空等 `NO_FRAME_FALLBACK_DELAY` 1000 毫秒，才冷启动 Media3。fast3 进程 30046 上，`HGSWITCH started` 到 `HGSWITCH audio native` 三次都正好差 1000 毫秒：19:12:50.310→19:12:51.315、19:17:12.602→19:17:13.602、19:18:49.660→19:18:50.661。海信在这次多余的解码器重启里把视频窗静音。

第二段在地址拿到之前。第一集、换频道、换一部剧不能预取，要等 `/api/v1/play/info`。fast3 上这一段从大约 0.5 秒到 17 秒都出现过（19:14:15 第一集 `foreground_resolve_ms=17296`；19:12:50 自动下一集预取未命中 `foreground_resolve_ms=5211`）。预取命中时这一段可以降到几十毫秒（19:17:12 `prefetch_ms=33 prepared=1`，19:18:49 `prefetch_ms=39 prepared=1`），但后面仍要付那 1000 毫秒。

声音曾有两次回归，用户已确认「现在有声音了」。一次是封面把元素静音抄进 Media3。一次是换到漫剧时，释放静音读到了还停在静音的 DOM。fast3 起用 `data-playback-audio-intent`，按音量偏好而不是元素静音来决定 Media3。

## 修改内容

- `core/cmd/hongguotv/ui/native-player.js`
  - 标准版只要 Media3 桥接存在，从第一帧起就留在桥接上。`resetToDomSource` 不再把地址交给 HTML 视频，也不再清掉 `native-playback`。
  - `play()` 直接 `invokePlay`。删掉 WebView 播放、1 秒无帧回退、15 秒失败回退、`armNativeFallback`、`startNativeFallback`、`fallbackToDom`、`domHasFrame`。
  - `invokePlay` 按 `intendedMuted()` 先 `setVolume`，再 `bridge.play`。封面静音不会把 Media3 静掉。`HGSWITCH audio native` 改在 `play()` 时打印，在 Media3 的 `started` 之前。
  - 没有桥接的桌面浏览器仍走 HTML 视频。MPV 构建仍走原来的固定原生路径。
- `core/cmd/hongguotv/ui/episode-prefetch.js`
  - 阈值 0 且时长还是 NaN 时允许开始预取。时长 0、Infinity、负数，以及默认阈值 5 下的 NaN，仍然不预取。
  - 仍然只预取一集。锁定集和 `accessible_episode_cnt` 没改。预取失败不改成整文件下载。
- `core/cmd/hongguotv/ui/app.js`
  - WebView 的 `prefetch_after_seconds` 为 0。真正开播后立刻 `maybePrefetchNextEpisode`。
  - 静音保持改为读音量偏好。释放时同时写真实 video 和代理。
- `core/cmd/hongguotv/ui/tv-focus.css`、`index.html`
  - 黑底、5 列海报、白底黑字焦点。海报焦点画在封面内侧。
- `android` 调试包：`applicationIdSuffix ".debug"`，显示名「红果短剧·快」，只打 `armeabi-v7a`。与已安装的 `rocks.aston.hongguotv` 0.2.109 并存。

没有改播放倍速、45 秒 Range 停滞、解密、清晰度、锁定判断。没有加第二个解码器。
